> A decision with no clear shape? Diagnose it, then point to one tool.

## When to use

A decision is on the table but you do not know which framework fits ("help me decide", "I'm stuck on", "should I"). Not for a decision whose shape is already obvious — run that tool directly.

## How it works

Diagnose the stuck-shape, then route to ONE tool. Do not run every framework.

| Stuck-shape | Route to |
|---|---|
| New opportunity, "should I pursue?" | [fate](../fate/) |
| Many known options, must choose | [mcdm](../mcdm/) |
| Big values-level life decision | [ooc-emr](../ooc-emr/) |
| Emotionally stuck, reacting | [ctfar](../ctfar/) |
| About to start something new | [ship-gate](../ship-gate/) |
| Reversible / trivial | skip the matrix, pick, move |

## Try it

`route should I take on the new client` → shape: new opportunity → run [fate](../fate/).

## Pitfalls

- Running several frameworks on one decision. Pick the one that fits.
- Defaulting to a matrix when the real block is emotional (that is [ctfar](../ctfar/), not [mcdm](../mcdm/)).

## Leads to

- new opportunity → [fate](../fate/)
- many options → [mcdm](../mcdm/)
- values-level → [ooc-emr](../ooc-emr/)
- stuck / reacting → [ctfar](../ctfar/)
- about to start → [ship-gate](../ship-gate/)
